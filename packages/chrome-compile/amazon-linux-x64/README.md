# Chromium 157 headless_shell — Amazon Linux 2023 x86_64

For EC2 launches, set `SSH_CIDR` to the public IPv4 range allowed to connect (normally your address with `/32`). `203.0.113.10/32` in the examples is a placeholder.

Builds Chromium **157.0.8080.0** `headless_shell` for Amazon Linux 2023 x86_64
inside a Docker container based on `amazonlinux:2023`.

Output: `chromium-headless-shell-amazon-linux2023-x64.zip` (~94 MB),
containing files inside a top-level
`chromium-headless-shell-amazon-linux2023-x64/` directory and including the
system `.so` files that AL2023 deployments need bundled. The wrapping folder
name is required by Remotion's `BrowserFetcher` — see top-level `README.md` →
"Output zip layout requirements".

## Chromium 157 notes

Changes relative to the 149 recipe (details in the root `README.md`):

- `enable_background_mode`, `enable_captive_portal_detection`,
  `enable_chrome_notifications`, `enable_platform_apps` and
  `enable_lens_desktop` are no longer forced off: `//chrome/test` and other
  full-graph targets now assert on them during `gn gen`.
- The build compiles the patched `page_handler.cc` objects right after
  `gn gen`, so a shared-memory patch error fails within minutes.
- Chromium's bundled Rust toolchain is used as-is (Step 12). Blink now needs
  headers generated by Crubit's `cc_bindings_from_rs`, which only accepts
  crates compiled by the rustc it ships with, so the rustup nightly that 149
  substituted is gone.
- `strip` skips zero-byte `libEGL.so` / `libGLESv2.so` placeholders.
- `setup-ec2.sh` keeps the container running and starts the build with
  `docker exec`, so a failed step can be fixed and resumed in place.

## Infrastructure

- **EC2**: `c6i.8xlarge` (32 Intel vCPU, 64 GiB RAM), 200 GiB gp3, eu-central-1
- **Docker base**: `amazonlinux:2023`
- **Build time**: ~1 h 20 min (single phase — pre-built LLVM, no bootstrap)

## Files

| File                | Purpose                                                        |
| ------------------- | -------------------------------------------------------------- |

| `setup-ec2.sh`      | Install Docker, build image, run the build, extract the zip    |

## Quick start

```bash
# 1. Launch EC2
SSH_CIDR=203.0.113.10/32 ./launch-ec2.sh

# 2. SCP files
scp -i chrome-build-key-al-x86.pem \
  Dockerfile build-chromium.sh ../shared/.gclient args.gn setup-ec2.sh \
  ../mac-arm64/remotion-shared-memory-v3.patch ../mac-arm64/probe-fast-path.py \
  ec2-user@<IP>:/home/ec2-user/

# 3. SSH & run
ssh -i chrome-build-key-al-x86.pem ec2-user@<IP> \
  'sudo cp /home/ec2-user/{Dockerfile,build-chromium.sh,.gclient,args.gn,setup-ec2.sh,remotion-shared-memory-v3.patch,probe-fast-path.py} /root/ && sudo bash /root/setup-ec2.sh'

# 4. Retrieve zip
ssh -i chrome-build-key-al-x86.pem ec2-user@<IP> \
  'sudo cp /root/chromium-headless-shell-amazon-linux2023-x64.zip /home/ec2-user/ && sudo chown ec2-user:ec2-user /home/ec2-user/chromium-headless-shell-amazon-linux2023-x64.zip'
scp -i chrome-build-key-al-x86.pem \
  ec2-user@<IP>:/home/ec2-user/chromium-headless-shell-amazon-linux2023-x64.zip .

# 5. Terminate
aws ec2 terminate-instances --instance-ids <id> --region eu-central-1
```

## Key differences from the Ubuntu x64 build

### Python 3.9 → 3.11

AL2023 ships Python 3.9, but `autoninja.py` in Chromium 149 uses
`from enum import StrEnum` (Python ≥ 3.11). After `gclient sync`, reuse the
Python 3.11 that `vpython` already downloaded:

```bash
PY311=$(ls -d /root/.cache/vpython-root.0/store/cpython+*/contents/bin/python3.11 | head -1)
ln -sf "$PY311" /usr/local/bin/python3
ln -sf "$PY311" /usr/bin/python3
ln -sf "$PY311" /usr/local/bin/python

mkdir -p /root/depot_tools/.cipd_bin
ln -sf "$PY311" /root/depot_tools/.cipd_bin/python3
echo ".cipd_bin" > /root/depot_tools/python3_bin_reldir.txt
```

### GCC triplet

AL2023 uses `x86_64-amazon-linux` (not `x86_64-linux-gnu`), and CRT objects
live in `/usr/lib64/`:

```bash
GCC_DIR=$(find /usr/lib/gcc/x86_64-amazon-linux/ -maxdepth 1 -type d | tail -1)
ln -sf "${GCC_DIR}/crtbeginS.o" /usr/lib64/crtbeginS.o
ln -sf "${GCC_DIR}/crtendS.o"   /usr/lib64/crtendS.o
```

### System libraries bundled

Unlike the Ubuntu x64 build (where the user `apt install`s deps), this output
bundles the .so files that Amazon Linux deployments need:

```
libnss3.so, libnssutil3.so, libsoftokn3.so, libnspr4.so, libexpat.so.1,
libplc4.so, libplds4.so, libfreebl3.so, libfreeblpriv3.so,
libdbus-1.so.3, libgcc_s*.so.1, libsystemd.so.0
```

### LLVM

Pre-built LLVM download (`tools/clang/scripts/update.py`) works on AL2023 x64
— glibc 2.34 is new enough. No bootstrap-from-source needed.

## Common build errors (what actually bit us on 149)

| Error                                                   | Cause                                  | Fix                                                             |
| ------------------------------------------------------- | -------------------------------------- | --------------------------------------------------------------- |
| `ImportError: cannot import name 'StrEnum' from 'enum'` | Python 3.9 on AL2023                   | Symlink vpython's 3.11 into `/usr/local/bin`                    |
| `python3_bin_reldir.txt not found`                      | depot_tools can't find python          | `mkdir .cipd_bin` + symlink + reldir file                       |
| `gn gen` asserts on `enable_extensions=false` etc.      | v149 build graph stricter              | Remove those flags; rely on defaults                            |
| `crtbeginS.o: No such file`                             | Wrong GCC CRT path on AL2023           | Use `x86_64-amazon-linux` triplet, symlink into `/usr/lib64`    |
| `unknown lang item: format_placeholder`                 | Wrong Rust nightly for bundled rustc   | Use `nightly-2026-02-28` (from VERSION file)                    |
| `KeyError: 'host'` in `run_build_script.py`             | `rustc` symlink points to rustup proxy | Symlink `$(rustup which rustc)`, not the proxy                  |
| `"third_party/rust-toolchain/bin/bindgen" missing`      | bindgen not installed                  | `cargo install bindgen-cli` + symlink                           |
| `"third_party/rust-toolchain/bin/rustfmt" missing`      | nightly installed without rustfmt      | `rustup … --component rustfmt` + symlink                        |
| Node.js version mismatch                                | v149 bundles a different Node          | Read version from `update_node_binaries`, download x64 directly |
| `SKIA_USE_DAWN used without USE_DAWN`                   | Dawn disabled but Skia Dawn wasn't     | `skia_use_dawn = false` in `args.gn`                            |
| `use_system_minigbm` build failure                      | Missing `gbm` library                  | `use_system_minigbm = false` in `args.gn`                       |

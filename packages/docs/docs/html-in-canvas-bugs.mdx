## Additional observed rendering differences

The following differences were reproduced on macOS with the unmodified Electron 46.0.0-alpha.6 release (Chromium 159.0.8130.0), with HTML-in-canvas enabled. Rendering comparisons used the same DOM rendered directly on the page and through `captureElementImage()` / `drawElementImage()` at the same size and pixel density. The OffscreenCanvas notification case was reproduced with the upstream web-platform test. These observations do not establish the status of later Chrome builds.

| Observed difference | Reproduction conditions |
| --- | --- |
| [Incorrect 3D occlusion](https://issues.chromium.org/issues/522872457) | Overlapping planes in a `transform-style: preserve-3d` scene, including `translateZ()` depth changes and intersecting `rotateY()` planes, can have a different front-to-back order. |
| Backfaces remain visible | A plane rotated away from the viewer can remain visible despite `backface-visibility: hidden`. |
| Positioned nested canvas is displaced | A child canvas positioned with `left: 70px; top: 30px` can paint at a different offset from the ordinary DOM version. Test positioning separately from a CSS translation. |
| Fractional fitted canvas edges differ | A 640×360 child canvas styled `width: 400px; height: 300px; object-fit: contain` has different edge coverage where the fitted content starts at a fractional coordinate. This is a remaining nested-canvas sampling case, separate from the fixed object-fit report above. |
| Blend, backdrop and mask effects differ | Intersecting 3D planes with `mix-blend-mode: screen` or `backdrop-filter: blur(...)` can produce different colors or blur results. A flat element combining a gradient mask, backdrop blur and blending can also omit content from a following sibling. |
| [OffscreenCanvas updates miss paint notifications](https://chromium-review.googlesource.com/c/chromium/src/+/8714422) | Committing new frames from a main-thread or worker `OffscreenCanvas` inside a drawable element can fail to fire `paint` on its ancestor canvas. The linked fix is under review; no fixed version is confirmed. |
| Masks differ under perspective | Compare a small, magnified plane with a linear-gradient mask, or an opacity group with a radial-gradient mask, under `perspective` and `rotateY()`. Masked edges and content can differ from the page. |
| Translucent groups differ at fractional scale | A group with `opacity: 0.5`, a box shadow, clipped children and an overflowing child has different edge coverage and colors under an ancestor `scale(0.625)`. |
| Very wide translucent groups differ | An `opacity: 0.5` group with `left: -50000px; width: 100000px`, containing visible colored children, differs under an ancestor `scale(0.625)`, including pixels inside the visible content. |

A [landed Chromium change](https://chromium.googlesource.com/chromium/src/+/1337fde1b6bb61c6dba4b184df3f30536a826573) improves forced merging of canvas descendants, but its commit description explicitly notes that descendant rendering remains incorrect. It is not a complete fix for the 3D cases above.

These are browser rendering observations, not confirmation that every visual difference violates the API specification. No upstream fix version is confirmed here. Experimental fixes in a custom Chromium build do not establish that a stock Chrome or Electron release contains a fix.

Keep an ordinary DOM reference when testing these cases. A preview and an export can share the same capture error, so agreement between those two alone is not a reliable reference.

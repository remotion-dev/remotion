# moveComposition()<AvailableFrom v="4.0.528" />

Moves a composition into a folder, to the root, or beside another registration.

:::warning

_Draft API_: This API is experimental and may change.

:::

```ts twoslash title="move-composition.ts"
import {moveComposition, type CodemodProject} from '@remotion/codemods';

declare const project: CodemodProject;

const result = moveComposition({
  project,
  compositionFile: 'src/Root.tsx',
  compositionId: 'MyComposition',
  destination: {type: 'folder', folder: {name: 'Social', parentName: null}},
});

console.log(result);
```

The composition and destination may be in different registration files supplied in `project.files`. The component implementation and composition ID stay unchanged. The composition must be a direct JSX child; a destination folder may also be the root element returned by a registration component.

For cross-file moves, imported dependencies are copied to the destination, relative imports are rebased, and conflicting import names are aliased. Imports still used in the source file are retained. Inline callbacks may use their own parameters and local variables when their scope can be established. Imported types are resolved separately from values. Ambiguous block-scoped bindings, assignments to external variables, and non-imported dependencies outside the moved JSX are rejected. Unsupported dependencies fail without changing either file.

## Options

### project

An in-memory [`CodemodProject`](/docs/codemods#project-model). The input project is not mutated.

### compositionFile

The project file containing the composition registrations. Registration edits support [`<Composition>`](/docs/composition), [`<Still>`](/docs/still), and [`<Folder>`](/docs/folder) with static IDs or folder names. Aliased and namespace imports from `remotion` are supported.

### compositionId

The static ID of the composition to edit.

### destination

Where to move the item. Use `{type: 'root'}`, `{type: 'folder', folder: {name, parentName}}`, or `{type: 'before' | 'after', target}`. A target is `{type: 'composition', compositionId}` or `{type: 'folder', name, parentName}`. Moving an item into its current parent in the same file is a no-op. Root moves stay in `compositionFile`.

### destinationFile

Optional project file containing the destination folder or registration. If omitted, a non-root destination must resolve uniquely among the project's JavaScript and TypeScript files. Supply this option to disambiguate identical folder names in different files. Folder ancestry is resolved from the JSX in the destination file; ancestry introduced by another component's caller is not inferred.

## Return value

Returns an object with the following properties.

### changes

An array of `{filePath, previousContents, nextContents}` file changes. A `null` content value indicates a created or deleted file.

### nodePathRemappings

An array of `{filePath, oldNodePath, newNodePath}` mappings. A `null` old path indicates an insertion; a `null` new path indicates removal. Apply these mappings to references from the input project. See [node references](/docs/codemods#node-references).

### updatedNode<AvailableFrom v="4.0.530" />

The moved registration's node reference in the new project.

## Errors

Throws when the target cannot be resolved, the requested edit is unsupported, or an option is invalid. Failed edits leave the input project unchanged.

# updateMultipleNodeProps()<AvailableFrom v="4.0.530" />

Updates props on multiple nodes across project files in one operation. Node references refer to the input project; the result includes their new paths.

:::warning

_Draft API_: This API is experimental and may change.

:::

```ts twoslash title="update-multiple-node-props.ts"
import {updateMultipleNodeProps, type CodemodProject, type NodeReference} from '@remotion/codemods';

declare const project: CodemodProject;
declare const title: NodeReference;
declare const background: NodeReference;

const result = updateMultipleNodeProps({
  project,
  changes: [
    {node: title, props: {children: 'Hello'}},
    {node: background, props: {'style.opacity': 0.5}},
  ],
});

console.log(result.changes, result.updatedNodes);
```

## Options

### project

An in-memory [`CodemodProject`](/docs/codemods#project-model). The input project is not mutated.

### changes

A non-empty array of node edits.

#### node

The [`NodeReference`](/docs/codemods#node-references) to edit, containing `filePath` and `nodePath`.

#### props?

A non-empty record of prop values, such as `{from: 30, 'style.opacity': 0.5}`. A value of `undefined` removes a prop. Only one level of nested keys is supported. Computed props, including values potentially overridden by a spread, are rejected. Supply exactly one of `props` or `updates` for each edit.

#### updates?

A non-empty array of [structured prop updates](/docs/codemods/update-node-props#updates) for edits that need default values or other update metadata. This form permits explicitly replacing computed prop values. Supply this instead of `props`.

#### schema?

A Remotion `InteractivitySchema` for schema-specific defaults and enum variants. By default, no schema-specific behavior is applied.

#### videoConfig?

The composition's `width`, `height`, `fps`, and `durationInFrames`, for evaluating supported expressions. By default, those runtime values are unknown.

### prettierConfigOverride?

Formatting options for inserted or changed source. By default, formatting is inferred from the source.

If any edit fails, no updated project is returned and the input project remains unchanged.

## Return value

### changes

An array of `{filePath, previousContents, nextContents}` file changes. A `null` content value indicates a created or deleted file.

### nodePathRemappings

An array of `{filePath, oldNodePath, newNodePath}` mappings. See [node references](/docs/codemods#node-references).

### updatedNodes

Updated node references in the same order as the requested edits.

### results

Per-node edit details in the same order as the requested edits: `oldValueStrings`, `logLine`, `removedProps`, and `newNodePath`. See [`updateNodeProps()`](/docs/codemods/update-node-props).

### formatted

`true` when the operation succeeds.

You can configure the Chromium or Google Chrome browser that Remotion launches for rendering.

:::note Default flags can change
Remotion’s default Chrome flags, including enabled and disabled features, can change between patch versions. There is no guarantee that these defaults remain unchanged. Overrides apply to the defaults of the installed Remotion version.
:::

## Custom flags<AvailableFrom v="4.0.543" />

Pass `chromiumOptions.flags` to add, replace, or remove individual flags:

```ts twoslash title="render.ts"
import {openBrowser} from '@remotion/renderer';
// ---cut---
const browser = await openBrowser('chrome', {
  chromiumOptions: {
    gl: 'angle',
    flags: {
      'disable-gpu-rasterization': true,
      'disable-gpu-compositing': true,
      'force-color-profile': 'display-p3',
      'disable-background-networking': false,
    },
  },
});
```

### `flags?`

<Options id="chromium-flags" />

The default is `{}`. Flag names must be lowercase and omit the leading `--`. A string replaces the complete value of a flag, including comma-separated lists. Use `features` or `blinkFeatures` to override individual entries in feature lists. Values are passed as individual process arguments; do not add shell quotes around them.

### `features?`

<Options id="chromium-features" />

The default is `{}`. Keys are feature names without parameters. To specify field trials or feature parameters, set the complete `enable-features` or `disable-features` string through `flags`.

### `blinkFeatures?`

<Options id="chromium-blink-features" />

The default is `{}`. This works like `features`, but modifies `enable-blink-features` and `disable-blink-features`.

```ts twoslash title="render.ts"
import {openBrowser} from '@remotion/renderer';
// ---cut---
const browser = await openBrowser('chrome', {
  chromiumOptions: {
    features: {Translate: false},
    blinkFeatures: {AudioVideoTracks: true},
  },
});
```

### Via CLI flags

Pass JSON objects. Each CLI option replaces the corresponding config value.

```sh title="Terminal"
bunx remotion render src/index.ts MyComposition out/video.mp4 \
  --chromium-flags='{"disable-gpu-rasterization":true,"disable-gpu-compositing":true}' \
  --chromium-features='{"Translate":false}' \
  --chromium-blink-features='{"AudioVideoTracks":true}'
```

### Via config file

Use [`Config.setChromiumFlags()`](/docs/config#setchromiumflags), [`Config.setChromiumFeatures()`](/docs/config#setchromiumfeatures), and [`Config.setChromiumBlinkFeatures()`](/docs/config#setchromiumblinkfeatures). These settings also apply to server renders started from the Studio. After changing the config, the new values apply to newly started render jobs.

```ts twoslash title="remotion.config.ts"
import {Config} from '@remotion/cli/config';
// ---cut---
Config.setChromiumFlags({
  'disable-gpu-rasterization': true,
  'disable-gpu-compositing': true,
});
Config.setChromiumFeatures({Translate: false});
Config.setChromiumBlinkFeatures({AudioVideoTracks: true});
```

For common settings, the dedicated options below are also available.

## `--disable-web-security`

This will most notably disable CORS among other security features.

:::note
Remotion will automatically append the `--user-data-dir` flag.
:::

### Via Node.JS APIs

Pass [`chromiumOptions.disableWebSecurity`](/docs/options/disable-web-security) in rendering APIs, including [`getCompositions()`](/docs/renderer/get-compositions), [`renderMediaOnVercel()`](/docs/vercel/render-media-on-vercel#chromiumoptions) and [`renderStillOnVercel()`](/docs/vercel/render-still-on-vercel#chromiumoptions).

### Via CLI flag

Pass [`--disable-web-security`](/docs/options/disable-web-security).

### Via config file

Use [setChromiumDisableWebSecurity()](/docs/config#setchromiumdisablewebsecurity).

```tsx twoslash
import {Config} from '@remotion/cli/config';

// ---cut---

Config.setChromiumDisableWebSecurity(true);
```

:::note
Prior to `v3.3.39`, the option was called `Config.Puppeteer.setChromiumDisableWebSecurity()`.
:::

## `--ignore-certificate-errors`

Results in invalid SSL certificates, such as self-signed ones, being ignored.

### Via Node.JS APIs

Pass [`chromiumOptions.ignoreCertificateErrors`](/docs/options/ignore-certificate-errors) in rendering APIs, including [`getCompositions()`](/docs/renderer/get-compositions), [`renderMediaOnVercel()`](/docs/vercel/render-media-on-vercel#chromiumoptions) and [`renderStillOnVercel()`](/docs/vercel/render-still-on-vercel#chromiumoptions).

### Via CLI flag

Pass [`--ignore-certificate-errors`](/docs/options/ignore-certificate-errors).

### Via config file

```tsx twoslash
import {Config} from '@remotion/cli/config';

// ---cut---

```

:::note

## `--disable-headless`

<Options id="disable-headless" />

Whether a window opens depends on the browser executable:

| Browser executable                                                                               | Opens a window                                |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------- |
| Default Chrome Headless Shell                                                                    | No. Chrome Headless Shell has no headed mode. |
| [Chrome for Testing](/docs/miscellaneous/chrome-headless-shell#using-chrome-for-testing-instead) | Yes.                                          |
| Custom desktop Chrome or Chromium                                                                | Yes.                                          |
| Custom Chrome Headless Shell                                                                     | No.                                           |

On Linux, headed mode requires a running display server. It is not available on Remotion Lambda, Cloud Run or Vercel.

### Via Node.JS APIs

Pass [`chromiumOptions.headless: false`](/docs/options/disable-headless) in rendering APIs, including [`getCompositions()`](/docs/renderer/get-compositions).

Also pass `chromeMode: 'chrome-for-testing'`, or provide a compatible desktop browser using `browserExecutable`.

### Via CLI flag

Pass [`--disable-headless`](/docs/options/disable-headless) together with `--chrome-mode=chrome-for-testing`:

```bash title="Render with a visible Chrome window"
npx remotion render ... --chrome-mode=chrome-for-testing --disable-headless
```

Alternatively, combine it with [`--browser-executable`](/docs/options/browser-executable) to use a custom desktop browser.

### Via config file

Use [setChromiumHeadlessMode()](/docs/config#setchromiumheadlessmode) and select Chrome for Testing:

```tsx twoslash title="remotion.config.ts"
import {Config} from '@remotion/cli/config';

// ---cut---

Config.setChromeMode('chrome-for-testing');
Config.setChromiumHeadlessMode(false);
```

:::note
Prior to `v3.3.39`, the option was called `Config.Puppeteer.setChromiumHeadlessMode()`.
:::

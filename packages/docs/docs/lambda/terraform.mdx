# Deploying Remotion Lambda with Terraform<AvailableFrom v="4.0.543" />

You can alternatively deploy a Remotion Lambda function using [Terraform](https://developer.hashicorp.com/terraform).  
Each release includes a regional manifest with the ZIP location, checksum, layers, and [runtime settings](/docs/lambda/runtime).

This example manages the Lambda function and its CloudWatch log group. You can also deploy your Remotion [site](/docs/terminology/serve-url) with Terraform using the optional [site configuration below](#option-2-deploy-with-terraform).

## Prerequisites

- Install [Terraform](https://developer.hashicorp.com/terraform/install).
- Create `remotion-lambda-role` with the Remotion role policy and a trust relationship for `lambda.amazonaws.com`. Follow [steps 2 and 3 of the setup guide](/docs/lambda/setup#2-create-role-policy).
- Configure [AWS credentials for Terraform](https://registry.terraform.io/providers/hashicorp/aws/latest/docs#authentication-and-configuration) for the account you want to deploy into. These credentials must be able to read and pass the role, and manage Lambda functions, tags, runtime settings, asynchronous invocation settings, and CloudWatch log groups. The [Remotion user policy](/docs/lambda/permissions#user-policies) alone may not cover all Terraform operations.

## Configure the function

Create the following files in a Terraform directory.

### Variables

Memory and disk space are separate settings, even though both default to `2048` MB here. Use whole numbers: `512`–`10240` for memory and disk space, and `15`–`900` for the timeout in seconds.

```hcl title="variables.tf"
variable "memory_size_mb" {
  type    = number
  default = 2048
}

variable "disk_size_mb" {
  type    = number
  default = 2048
}

variable "timeout_seconds" {
  type    = number
  default = 120
}
```

### Resources

Set `region` to a [supported region](/docs/lambda/region-selection) and `remotion_version` to the exact version used by your application. Hosted artifacts are available from `4.0.543`, except in [AWS China regions](/docs/lambda/aws-china-regions).

```hcl title="main.tf"
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
    http = {
      source  = "hashicorp/http"
      version = "~> 3.0"
    }
  }
}

locals {
  region           = "eu-central-1"
  remotion_version = "4.0.543"
  function_name    = "remotion-render-${replace(local.remotion_version, ".", "-")}-mem${var.memory_size_mb}mb-disk${var.disk_size_mb}mb-${var.timeout_seconds}sec"
  manifest         = jsondecode(data.http.manifest.response_body)
}

provider "aws" {
  region = local.region
}

data "http" "manifest" {
  url = "https://remotionlambda-binaries-${local.region}.s3.${local.region}.amazonaws.com/functions/v${local.remotion_version}/manifest.json"
}

data "aws_iam_role" "remotion" {
  name = "remotion-lambda-role"
}

resource "aws_cloudwatch_log_group" "remotion" {
  name              = "/aws/lambda/${local.function_name}"
  retention_in_days = 14
}

resource "aws_lambda_function" "remotion" {
  function_name = local.function_name
  role          = data.aws_iam_role.remotion.arn

  s3_bucket        = local.manifest.code.s3Bucket
  s3_key           = local.manifest.code.s3Key
  source_code_hash = local.manifest.code.sha256Base64

  handler       = local.manifest.handler
  runtime       = local.manifest.runtime
  architectures = [local.manifest.architecture]
  layers        = local.manifest.layers["default"]

  memory_size = var.memory_size_mb
  timeout     = var.timeout_seconds

  ephemeral_storage {
    size = var.disk_size_mb
  }

  tags = {
    "remotion-lambda"                   = "true"
    "remotion-version"                  = local.remotion_version
    "remotion-memory-in-mb"             = tostring(var.memory_size_mb)
    "remotion-timeout-in-seconds"       = tostring(var.timeout_seconds)
    "remotion-ephemereal-storage-in-mb" = tostring(var.disk_size_mb)
  }

  depends_on = [aws_cloudwatch_log_group.remotion]
}

resource "aws_lambda_function_event_invoke_config" "remotion" {
  function_name          = aws_lambda_function.remotion.function_name
  maximum_retry_attempts = local.manifest.maximumRetryAttempts
}

resource "aws_lambda_runtime_management_config" "remotion" {
  function_name       = aws_lambda_function.remotion.function_name
  update_runtime_on   = "Manual"
  runtime_version_arn = local.manifest.runtimeVersionArn
}

output "function_name" {
  value = aws_lambda_function.remotion.function_name
}
```

The ZIP remains in Remotion's regional S3 bucket. AWS Lambda can deploy code from a bucket in another account, as long as it is in the [same region as the function](https://docs.aws.amazon.com/lambda/latest/api/API_FunctionCode.html).

Keep the [function naming convention](/docs/lambda/naming-convention) and tags shown above so Remotion can discover the function and its configuration. The spelling of `remotion-ephemereal-storage-in-mb` is intentional.

The invocation configuration disables Lambda's automatic retries because Remotion handles retries. The [runtime management configuration](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/lambda_runtime_management_config) pins the runtime version used by that Remotion release.

### Override the defaults

For example, to use `3008` MB of memory and a `240` second timeout:

```hcl title="terraform.tfvars"
memory_size_mb  = 3008
disk_size_mb    = 2048
timeout_seconds = 240
```

## Deploy

```sh title="Deploy the function"
terraform init
terraform plan -out=tfplan
terraform apply tfplan
terraform output -raw function_name
```

If a function or log group with the same name already exists, [import it into Terraform](https://developer.hashicorp.com/terraform/language/import) before applying the configuration.

## Deploy a site

First, create a [Remotion Bundle](/docs/terminology/bundle) from your project:

```sh title="Build the site"
bunx remotion bundle src/index.ts --out-dir=build
```

Replace the entry point with your own. The bundle is relocatable by default and can be uploaded under a site prefix in S3. Choose one of the following deployment options. The bucket and function must be in the same region.

### Option 1: Deploy with Remotion

Use [`getOrCreateBucket()`](/docs/lambda/getorcreatebucket) and [`deploySiteFromBundle()`](/docs/lambda/deploysitefrombundle) to upload the bundle:

```ts twoslash title="deploy-site.ts"
import {deploySiteFromBundle, getOrCreateBucket} from '@remotion/lambda';

const region = 'eu-central-1';
const {bucketName} = await getOrCreateBucket({region});
const {serveUrl} = await deploySiteFromBundle({
  region,
  bucketName,
  bundleDir: './build',
});

console.log({serveUrl, bucketName});
```

### Option 2: Deploy with Terraform

Add `site.tf` alongside `main.tf`. Use an existing Remotion bucket, which you can create using [`getOrCreateBucket()`](/docs/lambda/getorcreatebucket). Your Terraform credentials also need permission to manage objects in this bucket.

The bundle must exist before running `terraform plan`. [`fileset()`](https://developer.hashicorp.com/terraform/language/functions/fileset) reads the local files while Terraform evaluates the configuration.

```hcl title="site.tf"
variable "bucket_name" {
  type = string
}

variable "site_name" {
  type    = string
  default = "my-video"
}

variable "bundle_dir" {
  type    = string
  default = "./build"
}

locals {
  site_bundle_dir = abspath(var.bundle_dir)
  site_prefix     = "sites/${var.site_name}"
  site_files      = fileset(local.site_bundle_dir, "**")
  site_content_types = {
    css   = "text/css"
    gif   = "image/gif"
    html  = "text/html"
    jpeg  = "image/jpeg"
    jpg   = "image/jpeg"
    js    = "text/javascript"
    json  = "application/json"
    mjs   = "text/javascript"
    mp3   = "audio/mpeg"
    mp4   = "video/mp4"
    otf   = "font/otf"
    png   = "image/png"
    svg   = "image/svg+xml"
    ttf   = "font/ttf"
    wasm  = "application/wasm"
    webm  = "video/webm"
    webp  = "image/webp"
    woff  = "font/woff"
    woff2 = "font/woff2"
  }
}

resource "aws_s3_object" "site_asset" {
  for_each = setsubtract(local.site_files, toset(["index.html"]))

  bucket      = var.bucket_name
  key         = "${local.site_prefix}/${each.value}"
  source      = "${local.site_bundle_dir}/${each.value}"
  source_hash = filemd5("${local.site_bundle_dir}/${each.value}")
  acl         = "public-read"
  content_type = try(
    local.site_content_types[lower(regex("[^.]+$", each.value))],
    "application/octet-stream"
  )
}

resource "aws_s3_object" "site_index" {
  bucket       = var.bucket_name
  key          = "${local.site_prefix}/index.html"
  source       = "${local.site_bundle_dir}/index.html"
  source_hash  = filemd5("${local.site_bundle_dir}/index.html")
  acl          = "public-read"
  content_type = "text/html"

  depends_on = [aws_s3_object.site_asset]
}

output "serve_url" {
  value = "https://${var.bucket_name}.s3.${local.region}.amazonaws.com/${aws_s3_object.site_index.key}"
}

output "bucket_name" {
  value = var.bucket_name
}
```

Set the bucket name and bundle location in your existing `terraform.tfvars`. Relative bundle paths are resolved from the directory where you run Terraform. Use letters, numbers, hyphens, or underscores for `site_name`.

```hcl title="terraform.tfvars (additional values)"
bucket_name = "remotionlambda-eucentral1-example"
site_name   = "my-video"
bundle_dir  = "../build"
```

This example uses public-read ACLs. If your bucket disables ACLs, remove both `acl` lines and configure its [bucket policy](/docs/lambda/bucket-security) to allow public `s3:GetObject` access to `sites/*`. All site assets must be publicly readable by the Lambda browser.

Add any other file extensions your project needs to `site_content_types`. The [`source_hash`](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_object) values make Terraform upload changed files. Terraform deletes previously managed files when they are removed from the bundle. Let Terraform exclusively manage this site prefix.

Apply the configuration and read the outputs:

```sh title="Deploy the prebuilt site"
terraform plan -out=tfplan
terraform apply tfplan
terraform output -raw serve_url
terraform output -raw bucket_name
```

## Render

Pass the deployed function name, site URL, and bucket to [`renderMediaOnLambda()`](/docs/lambda/rendermediaonlambda). Set `REMOTION_FUNCTION_NAME` from `terraform output -raw function_name`. Set `REMOTION_SERVE_URL` and `REMOTION_BUCKET_NAME` from your deployment script or the Terraform outputs above.

```ts twoslash title="render.ts"
import {renderMediaOnLambda} from '@remotion/lambda';

const functionName = process.env.REMOTION_FUNCTION_NAME;
const serveUrl = process.env.REMOTION_SERVE_URL;
const bucketName = process.env.REMOTION_BUCKET_NAME;

if (!functionName || !serveUrl || !bucketName) {
  throw new Error(
    'Set REMOTION_FUNCTION_NAME, REMOTION_SERVE_URL, and REMOTION_BUCKET_NAME.',
  );
}

const {renderId} = await renderMediaOnLambda({
  region: 'eu-central-1',
  functionName,
  serveUrl,
  composition: 'HelloWorld',
  codec: 'h264',
  forceBucketName: bucketName,
});

console.log({renderId, bucketName});
```

Replace the composition ID with your own, and configure [Remotion AWS authentication](/docs/lambda/authentication) for the script. Rebuild and deploy the site when your composition changes; subsequent renders can reuse its `serveUrl`. Use [`getRenderProgress()`](/docs/lambda/getrenderprogress) to track the render.

## Upgrading

Keep the function, site, and Remotion packages in your application on the same version. Changing `remotion_version`, memory, disk space, or timeout changes the function name and makes Terraform replace the function.

For [zero-downtime upgrades](/docs/lambda/upgrading#zero-downtime-upgrades), manage the old and new functions as separate Terraform resources or module instances. Deploy a new site, switch your application to the new function and site, and remove the old resources once their renders have finished. `create_before_destroy` alone does not keep the old function available until your application has switched.

For sites managed by Terraform, use a different `site_name` for each deployment and keep the old and new sites as separate resources or module instances during the transition. Changing `site_name` on the same resources moves the managed objects and removes the old site.

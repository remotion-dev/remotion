# npx remotion open-timeline import<AvailableFrom v="4.0.543" />

Imports an OpenTimelineIO (`.otio`) file as a new composition without starting Remotion Studio.

```bash title="Import a composition"
bunx remotion open-timeline import my-edit.otio
```

The command creates an editable composition, copies referenced local media into the public directory, and installs `@remotion/media` if needed. Media already in the public directory is reused. Remote media URLs are preserved.

Relative media paths are resolved from the timeline's directory. Use `--media-dir` to import media from another directory. Unsupported timeline features are reported before files are written; see [supported timelines](/docs/codemods/generate-open-timeline-composition#supported-timelines).

The command previews the files and dependencies, then asks for confirmation. Use `--yes` in scripts or `--dry-run` to preview without changing files.

## Flags

### `--composition`

The new composition ID. Defaults to the filename without its extension, with unsupported characters replaced by hyphens. For example, `my-edit.otio` becomes `my-edit`. Existing IDs are rejected; pass another ID with `--composition`.

### `--composition-file`

The existing TypeScript file containing the composition registrations, relative to the project root. By default, the command finds the registered root component from the project's entry point. If it cannot determine the file, pass it explicitly.

The generated component is created beside this file. Existing component files and conflicting assets are never overwritten.

### `--dry-run`

Validates the input and previews the composition, source files, assets, and dependencies without installing packages or writing files. Does not ask for confirmation.

### `--yes`

Imports without asking for confirmation. Also available as `-y`. Required in non-interactive shells unless `--dry-run` is passed.

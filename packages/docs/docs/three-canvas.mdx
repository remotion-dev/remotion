A wrapper for [React Three Fiber](https://github.com/pmndrs/react-three-fiber)'s `<Canvas />` which synchronizes with Remotions [`useCurrentFrame()`](/docs/use-current-frame).

Since React Three Fiber is a custom renderer, normally the React contexts that surround it don't work inside. This would normally break the usage of it in Remotion, but this component wraps the contexts so you can write your markup as expected.

Instead of using React Three Fibers `useFrame` API, you can (and must) write your animations fully declaratively using Remotions `useCurrentFrame` API. This will ensure that you can scrub back and forth in the timeline and pause the animation.

A browser bug [would normally cause the layout to be broken](https://github.com/pmndrs/react-three-fiber/issues/1394) because we apply a `scale` transform to the canvas in the Studio. To work around this problem, the `<ThreeCanvas />` requires the `width` and `height` props to be set.

## Example

A spinning, color changing, scaling cube. This example can also be found in the `examples` folder of the Remotion repo.

```tsx twoslash
import {ThreeCanvas} from '@remotion/three';
import {interpolate, useCurrentFrame, useVideoConfig} from 'remotion';

const ThreeBasic: React.FC = () => {
  const frame = useCurrentFrame();
  const {width, height} = useVideoConfig();

  return (
    <ThreeCanvas
      orthographic={false}
      width={width}
      height={height}
      style={{
        backgroundColor: 'white',
      }}
      camera={{fov: 75, position: [0, 0, 470]}}
    >
      <ambientLight intensity={0.15} />
      <pointLight args={[undefined, 0.4]} position={[200, 200, 0]} />
      <mesh position={[0, 0, 0]} rotation={[frame * 0.06 * 0.5, frame * 0.07 * 0.5, frame * 0.08 * 0.5]} scale={interpolate(Math.sin(frame / 10), [-1, 1], [0.8, 1.2])}>
        <boxGeometry args={[100, 100, 100]} />
        <meshStandardMaterial color={[Math.sin(frame * 0.12) * 0.5 + 0.5, Math.cos(frame * 0.11) * 0.5 + 0.5, Math.sin(frame * 0.08) * 0.5 + 0.5]} />
      </mesh>
    </ThreeCanvas>
  );
};

export default ThreeBasic;
```

## Props

### `from?`<AvailableFrom v="4.0.528" />

The frame at which the component becomes visible, relative to its parent. Defaults to `0`. See [`from`](/docs/sequence#from) on [`<Sequence>`](/docs/sequence).

### `durationInFrames?`<AvailableFrom v="4.0.528" />

How long the component stays visible. Defaults to `Infinity`, limited by its parent. See [`durationInFrames`](/docs/sequence#durationinframes) on [`<Sequence>`](/docs/sequence).

### `trimBefore?`<AvailableFrom v="4.0.528" />

Skips this many frames at the beginning of the content. Defaults to `0`. See [`trimBefore`](/docs/sequence#trimbefore) on [`<Sequence>`](/docs/sequence).

### `freeze?`<AvailableFrom v="4.0.528" />

Freezes the content at a local frame. Defaults to no freeze. See [`freeze`](/docs/sequence#freeze) on [`<Sequence>`](/docs/sequence).

### `hidden?`<AvailableFrom v="4.0.528" />

Hides the component and its children. Defaults to `false`. See [`hidden`](/docs/sequence#hidden) on [`<Sequence>`](/docs/sequence).

### `name?`<AvailableFrom v="4.0.528" />

The name shown in the Studio timeline. Defaults to `"<ThreeCanvas>"`. See [`name`](/docs/sequence#name) on [`<Sequence>`](/docs/sequence).

### `showInTimeline?`<AvailableFrom v="4.0.528" />

Whether to show the component in the Studio timeline. Defaults to `false`. See [`showInTimeline`](/docs/sequence#showintimeline) on [`<Sequence>`](/docs/sequence).

### `playbackRate?`<AvailableFrom v="4.0.528" />

Changes the speed of the content. Defaults to `1`. See [`playbackRate`](/docs/sequence#playbackrate) on [`<Sequence>`](/docs/sequence).

### `premountFor?`<AvailableFrom v="4.0.528" />

Mounts the component before its `from` frame, keeping it transparent and frozen at its first frame so assets can load. The value is a number of frames. Defaults to `0` in v4 and `fps` (1 second) in v5. See [premounting](/docs/player/premounting).

### `postmountFor?`<AvailableFrom v="4.0.528" />

Keeps the component mounted after its duration ends, transparent and frozen at its last frame. Defaults to `0` frames. Requires a finite `durationInFrames`.

### `styleWhilePremounted?`<AvailableFrom v="4.0.528" />

CSS styles applied while premounted. Defaults to no overrides. These styles override `style` and the default `opacity: 0` and `pointerEvents: 'none'`.

### `styleWhilePostmounted?`<AvailableFrom v="4.0.528" />

CSS styles applied while postmounted. Defaults to no overrides. These styles override `style` and the default `opacity: 0` and `pointerEvents: 'none'`.

Premounting and postmounting apply in the [Player](/docs/player) and [Studio](/docs/studio), and are disabled during rendering. They do not add a wrapper element.

## `frameloop` behavior during rendering

During rendering, `<ThreeCanvas>` overrides the `frameloop` prop to `'never'` regardless of what you pass. This means the Three.js scene will not re-render on its own — it is only re-rendered on demand via `advance()`.

If you update textures asynchronously (e.g. from a [`<Video>`](/docs/media/video) `onVideoFrame` callback), you must call `advance(performance.now())` instead of `invalidate()` to synchronously re-render the scene before the frame is captured. See [Using a video as a texture](/docs/videos/as-threejs-texture) for a full example.

## Note on `<Sequence>`

A [`<Sequence>`](/docs/sequence) by default will return a `<div>` component which is not allowed inside a `<ThreeCanvas>`. To avoid an error, pass `layout="none"` to `<Sequence>`.

# Importing OpenTimelineIO

Import an OpenTimelineIO (`.otio`) timeline as an editable Remotion [composition](/docs/terminology/composition). Clips become individual elements with their timing and trims preserved, so you can continue editing in [Remotion Studio](/docs/studio) or in code.

## In Remotion Studio<AvailableFrom v="4.0.542" />

<Step>1</Step> Open [Remotion Studio](/docs/studio) and choose **File → Import OpenTimeline...**. Select an `.otio` file.

### Referenced media

An `.otio` file describes an edit; it does not contain the video, audio, or image files. Keep the referenced media available when importing.

Studio resolves relative media paths from the `.otio` file's folder. Referenced local files are copied into the project's [public folder](/docs/assets); files already there and browser-accessible URLs are reused. If media cannot be found, click **Locate media...** and select its folder.

On macOS and Windows, local Studio uses a native file picker. With the browser file picker, the original file's folder is not available: use the **Media folder** field to resolve relative paths.

[Browser Studio](/docs/studio/remotion-dev-new) supports URLs and existing public assets. Import files from your computer using a local Studio. Importing is unavailable in read-only or disconnected Studios.

## Via the CLI<AvailableFrom v="4.0.543" />

Run this command from the Remotion project:

```bash title="Import a timeline"
bunx remotion open-timeline import my-edit.otio
```

The command creates and registers an editable composition, copies referenced local media into the public folder, and installs `@remotion/media` if needed.

Specify the composition ID, output dimensions, and frame rate with flags:

```bash title="Choose the composition settings"
bunx remotion open-timeline import my-edit.otio \
  --composition=MyEdit \
  --width=1920 \
  --height=1080 \
  --fps=30
```

Unlike Studio's frame-rate detection, the CLI defaults to 30 FPS. Width and height default to 1920 × 1080. Use `--media-dir=/path/to/media` if the files are stored in another folder, or `--dry-run` to preview the import without writing files or installing packages.

See the [CLI reference](/docs/cli/open-timeline/import) for all flags.

## Programmatically<AvailableFrom v="4.0.542" />

Install [`@remotion/codemods`](/docs/codemods) at the same version as the other Remotion packages in the project:

<Installation pkg="@remotion/codemods" />

[`generateOpenTimelineComposition()`](/docs/codemods/generate-open-timeline-composition) converts a timeline into TSX:

```ts twoslash title="import-timeline.ts"
import {readFileSync, writeFileSync} from 'node:fs';
import {generateOpenTimelineComposition} from '@remotion/codemods';

const result = generateOpenTimelineComposition({
  timeline: readFileSync('my-edit.otio', 'utf8'),
  componentName: 'MyEdit',
  width: 1920,
  height: 1080,
  fps: 30,
});

if (result.source === null) {
  throw new Error(JSON.stringify(result.diagnostics));
}

writeFileSync('src/MyEdit.tsx', result.source);
console.log(result.metadata, result.diagnostics);
```

Register the generated component as a [`<Composition>`](/docs/composition) using the returned metadata. To generate the component and its registration together, use [`addOpenTimelineComposition()`](/docs/codemods/add-open-timeline-composition).

The APIs operate in memory. They do not copy media or install dependencies. The generated component uses `remotion` and, when needed, `@remotion/media`. Put local media in the public folder, or map its references to browser-accessible URLs.

Remote URLs and public-relative paths work by default. For absolute paths, `file:` URLs, or missing media, provide a [`resolveMedia()` callback](/docs/codemods/generate-open-timeline-composition#resolvemedia). When source timecode does not start at zero, provide the media's `available_range` in the timeline; Studio and the CLI can probe local media automatically.

## Supported features and limitations

Importing supports clips, gaps, nested tracks, source trims, mixed frame rates, forward retiming, freeze frames, image sequences, and internal `SMPTE_Dissolve` transitions.

Other active effects are ignored with warnings. Reverse playback, custom transitions, and unsupported timeline structures can prevent importing. Application-specific crop, scale, and color adjustments are not interpreted. Video tracks import with embedded audio muted; include an audio track for sound.

Use `.otio` JSON files. Convert other interchange formats, including AAF, EDL, FCPXML, `.otioz`, and `.otiod`, to `.otio` first.

See [supported timelines](/docs/codemods/generate-open-timeline-composition#supported-timelines) for the full compatibility details.

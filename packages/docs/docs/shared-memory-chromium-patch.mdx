# Shared-memory Chromium Patch<AvailableFrom v="4.0.534" />

Traditionally, screenshots of webpages are captured using the [Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/), then encoded as either JPEG or PNG. Which one is used is determined by the [Video Image Format](/docs/renderer/render-media#imageformat) option.

Encoding these images is pure overhead, since FFmpeg later decodes them back into bitmaps. JPEG compression can also reduce image quality.

From v4.0.534, Remotion uses a special version of Chromium to optimize rendering in some cases. Instead of compressing each image, the bitmap is shared directly with Remotion's FFmpeg binary, which encodes it into a video.

## When it is used

Shared-memory capture is enabled automatically when all of these conditions are met:

- You use Remotion v4.0.534 or later on one of the supported platforms below.
- You are rendering a video. GIFs, audio-only renders, stills and image sequences are excluded.
- [Parallel encoding](/docs/parallel-encoding) is enabled: frames are rendered and encoded at the same time. This is the default for video renders.

| Platform                    | Requirements                                                                                                                                                                |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS                       | Apple Silicon Mac with macOS 13 or later                                                                                                                                    |
| Linux                       | x64 or ARM64 with glibc 2.35 or later, such as [Ubuntu 22.04](https://packages.ubuntu.com/jammy/libc6) or [Debian 12](https://packages.debian.org/bookworm/libc6) and newer |
| Amazon Linux                | Amazon Linux 2023, x64 or ARM64                                                                                                                                             |
| Remotion Lambda / Cloud Run | Deploy a new function or service using Remotion v4.0.534 or later                                                                                                           |

These requirements assume you use Remotion's [default browser](/docs/miscellaneous/chrome-headless-shell). On Windows, Intel Macs and older Linux systems, Remotion uses regular JPEG or PNG screenshots. Selecting [Chrome for Testing](/docs/miscellaneous/chrome-headless-shell#using-chrome-for-testing-instead) also uses regular screenshots.

The patch does not apply to previews or [client-side rendering](/docs/client-side-rendering).

## Image format and quality

When shared-memory capture is active, both `imageFormat: "jpeg"` and `imageFormat: "png"` send uncompressed bitmaps to FFmpeg. Switching between them no longer changes the image compression or capture quality.

The option still controls the background:

- `"jpeg"` uses an opaque black background for areas not painted by your composition.
- `"png"` preserves transparency during capture. Follow the [transparent video guide](/docs/transparent-videos) to choose an output codec and pixel format that preserve transparency in the final video.

The [`jpegQuality`](/docs/renderer/render-media#jpegquality) option has no effect on video frames captured through shared memory. When Remotion falls back to screenshots, the image format and JPEG quality options work as before.

Shared-memory capture avoids the extra JPEG compression step. The final video is still compressed according to your [codec and quality settings](/docs/encoding). Overall render speed depends on your composition, encoder and machine.

## Check whether it is active

Render with [verbose logging](/docs/troubleshooting/debug-failed-render):

```bash title="Check capture mode"
npx remotion render MyComp --log=verbose
```

A log message beginning with `Remotion shared-memory capture uses` confirms that the patch is active. Parallel encoding can also work with regular screenshots, so the parallel encoding message alone does not confirm shared-memory capture.

With [`renderMedia()`](/docs/renderer/render-media), set `logLevel: "verbose"` to see the same information.

## Opt out

Disable parallel encoding to use regular JPEG or PNG screenshots:

```bash title="Render without shared-memory capture"
npx remotion render MyComp --disallow-parallel-encoding
```

With [`renderMedia()`](/docs/renderer/render-media#disallowparallelencoding), set `disallowParallelEncoding: true`.

For CLI and Studio renders, you can also use [`Config.setDisallowParallelEncoding()`](/docs/config#setdisallowparallelencoding):

```ts twoslash title="remotion.config.ts"
import {Config} from '@remotion/cli/config';

Config.setDisallowParallelEncoding(true);
```

This also makes frame rendering and encoding happen in separate stages, which can reduce peak memory usage but may make rendering slower. Lambda and Cloud Run currently do not expose this option.

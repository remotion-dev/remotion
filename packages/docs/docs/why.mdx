In a world with 1,000 video creation tools, why would you want to use Remotion?

## You want your video to be code

Code can express what a graphical user interface never could. Code can be encapsulated and reused. Code can scale. Code will connect to your data. Code has the best option for version control. Code is understood by your agents. Code can be automated.

## You want to use web technology

The web is the world's most popular graphics engine. Everybody has it installed. It gives you layout, typography, media, shaders, vectors, and 3D out of the box. It has gone through immense battle-testing and obsessive performance optimization. The web is open and its ecosystem is massive.

## You want to compose your video

You want to encapsulate your elements and behaviors. You want to have 10 individually toggleable layers. You want to apply a shader to your HTML, then lay out and decorate it using CSS, then multiply it 5 times and add motion blur on top of all. You want to reuse and parameterize your elements.

## You want the best rendering options

You want to be able to render with the click of a button, from the [command line](/docs/cli/render), or programmatically using an [API](/docs/renderer). You want to export videos, [stills](/docs/stills), [GIFs](/docs/render-as-gif), and [image sequences](/docs/render#image-sequence). You want a [well](/blog/faster-lambda)-[optimized](/docs/shared-memory-capture) render pipeline. You want to render on all operating systems in Node.js in any [Docker](/docs/docker) container or in [Electron](/docs/electron). You want to render on [AWS Lambda](/docs/lambda), [Cloudflare](/docs/cloudflare-containers), [Azure](/docs/azure-container-apps) and on [Vercel](/docs/vercel-sandbox). You want to render [directly in the browser](/docs/client-side-rendering). You want to be able to render millions of videos.

## You want to build an application

You want to embed a [video player](/player) into your app. You want it to [connect to your data](/docs/parameterized-rendering). You want your player to be an interactive canvas. You want to [start with a template](/docs/editor-starter). You want to build on a foundation already used by over 2,000 [websites](https://www.wappalyzer.com/technologies/video-players/remotion/).

## You want to be empowered, not exploited

You don't want to be pushed towards a hosted platform. You don't want to log into an account. You don't want features to be paywalled. You don't want to be sold tokens or AI generations.

Remotion's business model is simple. It [costs money for companies](/docs/license/faq) of 4+ people. For everyone else it is free.<br />
This works and we don't have to make our product annoying.

## You don't want to reinvent

You want [building blocks](/elements), [templates](/templates), [transitions](/docs/transitions), and [effects](/docs/effects) to be there. You want to leverage our work of [thousands of iterations](https://github.com/remotion-dev/remotion/pulls?q=sort%3Aupdated-desc+is%3Apr+state%3Aclosed) from hundreds of contributors. You want to be in an open ecosystem where [third-party component libraries](/elements/libraries), [video editor templates](/docs/buy-a-video-editor), editing interfaces and [skills](https://github.com/Vincentwei1021/video-shotcraft) can exist.

## You want to be certain

We are a sustainable, growing business. [No VCs.](/docs/investors) Since 2021, we [continuously improve Remotion](https://github.com/remotion-dev/remotion/commits/main/) almost every day.<br />
We don't have plans to change our business model or sell Remotion.

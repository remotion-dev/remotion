Regular video editors are canvas-based which allows for complex effects and compositing that is not possible with plain CSS.

[HTML-in-canvas](https://github.com/WICG/html-in-canvas) is an experimental browser API available in Chrome and other Chromium-based browsers behind a flag, which allows you to draw a live DOM node into a `<canvas>` and post-process it with the Canvas 2D API, WebGL or WebGPU.

Remotion offers a [`<HtmlInCanvas>`](/docs/remotion/html-in-canvas) component, [transitions](#with-remotiontransitions) and HTML-in-canvas-based client-side rendering.

## Enabling the flag in Chrome

To preview HTML-in-canvas effects in the [Remotion Studio](/docs/studio), use [Google Chrome](https://www.google.com/chrome/) v149 or later and enable a flag:

1. Install or update [Google Chrome](https://www.google.com/chrome/).
2. Open `chrome://flags/#canvas-draw-element`.
3. Set the `HTML-in-Canvas` flag to `Enabled` and restart.

To check at runtime whether HTML-in-canvas is supported, you can use [`HtmlInCanvas.isSupported()`](/docs/remotion/html-in-canvas#htmlincanvasissupported).

For rendering, you don't need to do anything — see [Rendering](#rendering) below.

## The `<HtmlInCanvas>` component

[`<HtmlInCanvas>`](/docs/remotion/html-in-canvas) is a convenient component which wraps its children in a canvas and allows you to manipulate the content when the canvas is painted.

```tsx twoslash title="MyComp.tsx"
import {HtmlInCanvas, type HtmlInCanvasOnPaint} from 'remotion';

const onPaint: HtmlInCanvasOnPaint = ({canvas, elementImage}) => {
  const ctx = canvas.getContext('2d');
  if (!ctx) {
    throw new Error('Failed to acquire 2D context');
  }

  ctx.reset();
  ctx.filter = 'blur(8px)';
  ctx.drawElementImage(elementImage, 0, 0);
};

export const MyComp: React.FC = () => {
  return (
    <HtmlInCanvas width={1280} height={720} onPaint={onPaint}>
      <div style={{fontSize: 80}}>Hello</div>
    </HtmlInCanvas>
  );
};
```

See the [`<HtmlInCanvas>`](/docs/remotion/html-in-canvas) reference for the full API, including WebGL and WebGPU examples.

### Using the browser API directly

You can also use the browser API directly. Refer to the [working draft](https://github.com/WICG/html-in-canvas) to do so.  
If you do so, you are responsible yourself for calling [`delayRender()`](/docs/delay-render) and [`continueRender()`](/docs/continue-render) to synchronize paint operations.

## Limitations

HTML-in-canvas is only available in Chrome 149 and later with the `chrome://flags/#canvas-draw-element` flag enabled.  
The API is unstable - Chrome may change the API or even remove it in the future.

Nesting [`<HtmlInCanvas>`](/docs/remotion/html-in-canvas) components requires Chrome 157.0.8080.0 or newer with HTML-in-canvas enabled. See [Nested HTML-in-canvas](#nested-html-in-canvas).

### Cross-origin content

HTML-in-canvas [omits cross-origin content that JavaScript cannot read](https://github.com/WICG/html-in-canvas#read-back-allowed-rendering), including images and videos loaded without CORS, cross-origin iframes and tainted canvases. Content can appear in the regular page while being absent from the captured canvas.

From <AvailableFrom v="4.0.542" inline />, [`<Img>`](/docs/img) and [`<Html5Video>`](/docs/html5-video) default to `crossOrigin="anonymous"` inside `<HtmlInCanvas>`, including [`<HtmlInCanvasMotionBlur>`](/docs/motion-blur/html-in-canvas-motion-blur). This also applies to [`<OffthreadVideo>`](/docs/offthreadvideo) during preview. The media server must allow CORS. In earlier versions, set `crossOrigin="anonymous"` explicitly.

If the server rejects CORS, these components report a loading error instead of silently disappearing from the canvas. Anonymous CORS omits cross-origin credentials; for authenticated media, see [`<Img>`'s `crossOrigin` prop](/docs/img#crossorigin) or [`<Html5Video>`'s `crossOrigin` prop](/docs/html5-video#crossorigin).

For native `<img>` and `<video>` elements, set `crossOrigin="anonymous"` yourself. SVG `<image>` elements also support this attribute. CSS background images have no `crossOrigin` attribute; use a same-origin URL, a data URL, or a blob URL created from a successful CORS fetch. If a remote server does not allow CORS, host the asset in your [public folder](/docs/assets).

## Rendering

From [`v4.0.455`](https://github.com/remotion-dev/remotion/releases/tag/v4.0.455), render is supported locally via [`npx remotion render`](/docs/cli/render) and Studio, on [Lambda](/docs/lambda), on [Vercel](/docs/vercel) and through [server-side rendering](/docs/ssr) APIs.

We compiled a version of Chrome and made it the default, and enabled the flag for you.

Nested `<HtmlInCanvas>` components are supported during server-side rendering from Remotion <AvailableFrom v="4.0.534" inline />, which uses Chromium 157.0.8080.0.

If your effect uses a WebGL shader, pass [`--gl=angle`](/docs/gl-options) to make the render work:

```bash
npx remotion render --gl=angle
```

Set it as the default in [`remotion.config.ts`](/docs/config) so Studio and CLI renders pick it up as a default:

```ts twoslash title="remotion.config.ts"
import {Config} from '@remotion/cli/config';
// ---cut---
Config.setChromiumOpenGlRenderer('angle');
```

If your machine has no GPU, we recommend `--gl=swangle` instead (default on Lambda).

## Leveraging HTML-in-canvas for client-side rendering

Not directly related, but [`@remotion/web-renderer`](/docs/client-side-rendering/html-in-canvas) can also use this technology to capture frames.

This is opt-in. In browsers without nesting support, compositions containing [`<HtmlInCanvas>`](/docs/remotion/html-in-canvas) use the built-in DOM composer because native capture would create a nested HTML-in-canvas subtree.

## Nested HTML-in-canvas

Nesting `<HtmlInCanvas>` components is supported in Chrome 157.0.8080.0 or newer with HTML-in-canvas enabled. Use [`HtmlInCanvas.isNestingSupported()`](/docs/remotion/html-in-canvas#htmlincanvasisnestingsupported) to check at runtime. Unsupported browsers throw an error when components are nested. Server-side rendering supports nesting from Remotion <AvailableFrom v="4.0.534" inline />.
